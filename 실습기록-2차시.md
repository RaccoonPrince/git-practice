# 2차시 실습 기록 (2026-10-16, Claude가 실행한 그대로)

> 나중에 같은 순서로 직접 따라 하세요. 각 단계 끝에 `git status` 와 `git log --graph --oneline --decorate --all` 로 확인하는 습관을 들이면 좋아요.
> 이 저장소는 main에 `sub`, `div` 가 이미 commit돼 있어서, 수업노트의 sub/div 대신 **`mod`, `pow2`** 로 branch 실습을 했어요. 순서와 명령은 수업노트와 같아요.
> 파일이 Windows 줄바꿈(CRLF)이라 `LF will be replaced by CRLF` 경고가 뜨는데 무시해도 돼요.
> 아래 "파일 수정"은 VS Code에서 직접 하면 됩니다. 들여쓰기는 이 파일처럼 **탭**이에요.

## 단계 2. diff → stage → commit
`calculator.py` 에 `multi` 함수를 추가해 둔 상태에서:
```bash
git diff                                # 바뀐 내용 확인
git add calculator.py                   # Staging Area에 올리기
git diff --staged                       # commit될 내용 확인
git commit -m "Add multiply function"   # 저장
git log --oneline
```

## 단계 4. 자동 merge
**4-1. feature/mod (add 바로 아래에 함수 추가)**
```bash
git switch -c feature/mod               # 새 branch 만들고 이동
```
`print(add(10,5))` 아래에 추가:
```python
def mod(a,b):
	return a%b
print(mod(10,3))
```
```bash
git diff
git add calculator.py
git commit -m "Add mod function"
```
**4-2. 반드시 main으로 돌아가서 feature/pow 만들기 (파일 맨 아래에 추가)**
```bash
git switch main
git switch -c feature/pow
```
파일 맨 아래에 추가:
```python
def pow2(a,b):
	return a**b
print(pow2(2,3))
```
```bash
git diff
git add calculator.py
git commit -m "Add pow function"
git log --graph --oneline --decorate --all    # 두 갈래로 갈라진 것 확인
```
**4-3. main에 차례로 merge**
```bash
git switch main
git merge feature/mod                   # Fast-forward (새 commit 없이 이름표만 이동)
git merge feature/pow                   # 진짜 merge → merge commit 생김 (편집기가 뜨면 저장하고 닫기, vim은 :wq)
python calculator.py                    # 15 1 5 2.0 50 8 출력되면 성공
git log --graph --oneline --decorate --all
```

## 단계 5. Conflict
**5-1. 첫 번째 branch**
```bash
git switch -c feature/add-validation
```
`def add(a,b):` 바로 아래 줄에 추가:
```python
	print("add called")
```
```bash
git diff
git add calculator.py
git commit -m "Add logging to add"
```
**5-2. 다시 main에서 두 번째 branch (같은 위치, 다른 글자)**
```bash
git switch main
git switch -c feature/add-message
```
`def add(a,b):` 바로 아래 줄에 추가:
```python
	print("calculating...")
```
```bash
git add calculator.py
git commit -m "Add message to add"
git log --graph --oneline --decorate --all
```
**5-3. 첫 번째 merge (정상, Fast-forward)**
```bash
git switch main
git merge feature/add-validation
```
**5-4. 두 번째 merge → 충돌**
```bash
git merge feature/add-message           # CONFLICT (content): Merge conflict in calculator.py
git status                              # both modified: calculator.py
```
calculator.py 를 열면 이렇게 보여요:
```
def add(a,b):
<<<<<<< HEAD
	print("add called")
=======
	print("calculating...")
>>>>>>> feature/add-message
	return a+b
```
**5-5. (선택) 해결을 포기해 보기**
```bash
git merge --abort                       # merge 시작 전으로 돌아감
git status                              # 깨끗해졌는지 확인
git merge feature/add-message           # 다시 충돌 상태로
```
**5-6. 해결**: 마커 3줄(`<<<<<<<`, `=======`, `>>>>>>>`)을 지우고 두 줄을 다 남겨요.
```python
def add(a,b):
	print("add called")
	print("calculating...")
	return a+b
```
```bash
git status                              # 아직 both modified (고친 것 ≠ 해결했다고 알린 것)
git add calculator.py                   # "해결 완료" 표시
git commit -m "Resolve add function conflict"
python calculator.py                    # add called / calculating... / 15 ...
git log --graph --oneline --decorate --all   # 부모가 둘인 merge commit
```

## 단계 6. pull 전략 (개념만)
실행은 하지 않았어요. 원격과 이력이 갈라졌을 때 `git pull --no-rebase`(merge), `--rebase`(내 commit을 뒤에 새로 붙임), `--ff-only`(갈라지면 중단) 중에 고른다는 것만 알면 돼요.

## 단계 7. 되돌리기
**7-1 restore**: 파일 끝에 `# temp` 한 줄을 추가한 뒤
```bash
git diff                                # 사라질 내용 먼저 확인
git restore calculator.py               # 수정 버리기 (복구 불가!)
git status
```
**7-2 restore --staged**: `# temp` 를 다시 추가한 뒤
```bash
git add calculator.py
git restore --staged calculator.py      # 장바구니에서만 내림 (파일 내용은 유지)
git status                              # Changes not staged 로 바뀜
git restore calculator.py               # 정리
```
**7-3 reset --soft** (실습용 branch에서만!)
```bash
git switch -c practice/reset
```
`# temp` 추가 후
```bash
git add calculator.py
git commit -m "temp commit"
git reset --soft HEAD~1                 # commit만 취소, 변경은 stage에 남음
git status
git restore --staged calculator.py      # 정리
git restore calculator.py
git switch main
git branch -d practice/reset
```
**7-4 revert** (main에서): `# temp` 추가 후
```bash
git add calculator.py
git commit -m "Add temp comment"
git revert HEAD                         # 편집기가 뜨면 저장하고 닫기 (vim은 :wq)
git log --oneline                       # 취소하는 새 commit(Revert "...")이 쌓임
```
